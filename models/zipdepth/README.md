# ZipDepth

- **[ZipDepth](https://arxiv.org/abs/2607.08771)** (ECCV 2026)
- **[ZipDepth official GitHub](https://github.com/fabiotosi92/ZipDepth)**
- 2d image -> affine-invariant inverse depth

## At a Glance

| Item | Repository configuration |
| :--- | :--- |
| Input | RGB image, `384x512` for the repository example |
| Output | Affine-invariant inverse depth |
| Scale | Relative; values are not metres |
| TensorRT target | `base`, FP16 |

## Supported Encoders

| Used here | Released upstream configurations |
| :--- | :--- |
| `base` | `base`, `base_npu` |

Both checkpoints use the same 6.1M-parameter base network. `base_npu` replaces
the convex upsampler for deployment compatibility; it is a different
checkpoint, not a smaller encoder.

## Model-Specific Notes

Every other model in this repository is a ViT or a transformer geometry
network, and the fastest of them is a ViT-S. ZipDepth is **6.1M parameters of
reparameterised convolutions**. It is here to put a point somewhere else on the
latency curve rather than another row in the middle of it, and to make
TensorRT's convolution-fusion path carry a row instead of its attention path
carrying all of them.

Three things differ from the rest of the table and will bite if assumed away:

| | |
| :--- | :--- |
| **Preprocessing is `/255` only** | No ImageNet mean, no standard deviation. Every other model here subtracts them; doing it to ZipDepth feeds it an image it has never seen. |
| **Output is inverse depth** | Large means near. It has no unit and no zero, so it is scored after a scale-and-shift fit -- and the fit is on disparity, which is the form the output is already in. |
| **384x512, multiples of 32** | Upstream resizes the short side to 384 and rounds both sides to a multiple of 32; for the 4:3 of `data/example.jpg` that is 384x512. A different aspect ratio needs a different engine. |

## PyTorch Setup and Inference

```
cd models/zipdepth
git clone https://github.com/fabiotosi92/ZipDepth.git

conda create -n zipdepth -y python=3.10
conda activate zipdepth
cd ZipDepth
pip install -r requirements.txt
pip install -e .
pip install onnx onnxsim
```

The checkpoints are committed in the upstream repository -- `checkpoints/zipdepth_base.pth`
and `checkpoints/zipdepth_base_npu.pth`, about 27 MB each -- so the clone is
the whole download. There is no separate weights step, which is unique here.

```
python scripts/infer.py --checkpoint checkpoints/zipdepth_base.pth \
    --input ../../../data/example.jpg --input-size 384
```

## ONNX Export and TensorRT

1. generate the onnx file.
    ```
    conda activate zipdepth
    python onnx_export.py
    // onnx/zipdepth_base_384x512.onnx
    ```

2. build the engine and benchmark.
    ```
    conda activate trte
    python onnx2trt.py
    // engine/zipdepth_base_384x512_fp16.engine
    ```

**If TensorRT struggles with the convex upsampling**, set `npu = True` in both
scripts. Upstream ships a second checkpoint built without the `unfold`-based
upsampler for exactly this reason, and `Unfold` is one of the operators
TensorRT handles unevenly. That is a fallback with a different set of weights,
not a build flag -- the numbers from the two are not the same model's.
