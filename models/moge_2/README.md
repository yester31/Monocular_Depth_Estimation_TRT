### ONNX exporter A/B

The four combinations of Dynamo/TorchScript and raw/simplified ONNX were each
built independently three times at a pinned 1800 MHz GPU clock. No alternative
cleared the project's 2% decision threshold, and Reformat+Slice remained
32.95–34.28% in every representation. The current Dynamo + simplified graph
had the lowest mean (19.786 ms) and smallest build span (0.35%), so it stays.
All 12 experimental engines passed their own ONNX accuracy check. Full method,
per-build results, graph counts, and raw JSON are in
[`reports/tune/moge_ab`](../../reports/tune/moge_ab/README.md).

> The per-run figures further down are historical: they predate the
> unified timing loop, when warmup varied between 5 and 20 and nothing
> recorded the GPU or TensorRT version. The block above is generated
> from an actual measurement; those are not.

## How to Run (Pytorch)

1. set up a virtual environment.
    ```
    cd MoGe_2
    git clone https://github.com/microsoft/MoGe.git
    cd MoGe

    # Create a new conda environment with Python 3.11
    conda create -n MoGe -y python=3.11

    # Activate the created environment
    conda activate MoGe

    # Install the required Python packages
    pip install -r requirements.txt 
    pip install git+https://github.com/microsoft/MoGe.git
    pip install pyglet==1.5.29
    pip install onnx
    pip install onnxsim
    ```

2. download pretrained checkpoints.
    ```
    mkdir -p checkpoint/moge-2-vitl
    wget https://huggingface.co/Ruicheng/moge-2-vitl/resolve/main/model.pt -P checkpoint/moge-2-vitl

    mkdir -p checkpoint/moge-2-vitl-normal
    wget https://huggingface.co/Ruicheng/moge-2-vitl-normal/resolve/main/model.pt -P checkpoint/moge-2-vitl-normal

    mkdir -p checkpoint/moge-2-vitb-normal
    wget https://huggingface.co/Ruicheng/moge-2-vitb-normal/resolve/main/model.pt -P checkpoint/moge-2-vitb-normal

    mkdir -p checkpoint/moge-2-vits-normal
    wget https://huggingface.co/Ruicheng/moge-2-vits-normal/resolve/main/model.pt -P checkpoint/moge-2-vits-normal
    ```

3. run the original pytorch model on test images.
    ```
    moge infer -i ../../data -o outputs --maps --glb --ply
    ```

4. check pytorch model inference performance
    ```
    cd ..
    python infer.py
    ```

## How to Run (TensorRT)

1. generate onnx file
    ```
    python onnx_export.py
    // a file 'moge-2-vits-normal_dynamic_sim.onnx' will be generated in onnx directory.
    ```

2. build tensorrt model and run
    ```
    conda activate trte
    pip install "utils3d @ git+https://github.com/EasternJournalist/utils3d.git@3fab839f0be9931dac7c8488eb0e1600c236e183"
    pip install trimesh
    python onnx2trt.py
    // a file 'moge-2-vits-normal_fp16_dynamic_sim.engine' will be generated in engine directory.
    ```

> **This step used to name commit `c5daf6f6`**, which contradicts the root
> README and `metric_anything`, both of which pin `3fab839f` — the commit MoGe
> itself pins. Only one of the two can be installed in `trte`, and the working
> pipeline uses `3fab839f`, so that is the one named here now.
>
> **The textured-mesh output is off** (`export_mesh = False` in `onnx2trt.py`).
> That block was written against `c5daf6f6`, where three of the calls it makes
> have different names and signatures:
>
> | used here | name in `3fab839f` |
> | :--- | :--- |
> | `depth_edge` | `depth_map_edge` |
> | `image_uv` | `uv_map` |
> | `image_mesh` | `build_mesh_from_map` (different return tuple) |
>
> Depth, points, normals, fov and the benchmark are unaffected — only the
> `.ply` is not written. Porting it means re-deriving the mesh construction and
> looking at the result, which is why it is disabled rather than half
> translated. `onnx2trt_pointcloud.py` does not use those calls and works.
